# AA55 Protocol (Unencrypted)

**Integration mode:** 1
**Controller app evidence:** AirHeaterBLE `AA66Or55Old` parser and AA-family
command builder

## Transport

| Item | Value |
| --- | --- |
| Service | `0000FFE0-0000-1000-8000-00805F9B34FB` |
| Read/write/notify characteristic | `0000FFE1-0000-1000-8000-00805F9B34FB` |
| Status header | `AA 55` |
| Status length | 18-20 bytes |

## Status frame

| Offset | Field | Interpretation |
| --- | --- | --- |
| 0-1 | Header | `AA 55` |
| 3 | Running state | Controller state value |
| 4 | Error code | AA55 error position |
| 5 | Running step | Controller step value |
| 6-7 | Altitude | Little-endian unsigned value |
| 8 | Running mode | `1` level, `2` temperature, `3` manual |
| 9 | Set value | Level in level mode; target temperature in temperature mode |
| 10 | Active level | Zero-based level in temperature and manual modes |
| 11-12 | Supply voltage | Little-endian unsigned value, divided by 10 |
| 13-14 | Case temperature | Little-endian signed 16-bit value |
| 15-16 | Cabin temperature | Little-endian signed 16-bit value |

The integration uses byte 10 plus one for the displayed level in temperature
and manual modes. It does not claim a universal meaning for remaining bytes.

## Commands

```text
AA 55 PIN_HI PIN_LO COMMAND ARG_LO ARG_HI CHECKSUM
```

`PIN_HI` is `PIN // 100`; `PIN_LO` is `PIN % 100`. The checksum is the sum of
bytes 2 through 6 modulo 256. AA55 commands are unencrypted even when a
related AA-family controller sends encrypted status notifications.

## Detection

AA55 is selected only after a valid 18- or 20-byte `AA 55` notification is
received on the AA-family transport.
