# AA66 Protocol (Unencrypted)

**Integration mode:** 3
**Controller app evidence:** AirHeaterBLE `parseBluetoothData.js`, parser `AA66Or55Old`

## Scope

AA66 is an unencrypted 20-byte status protocol in the AirHeaterBLE family. It
uses the same eight-byte `AA 55` command packet as the other AA-family
controllers; the response header, not the command header, distinguishes AA66.

## Transport

| Item | Value |
| --- | --- |
| Service | `0000FFE0-0000-1000-8000-00805F9B34FB` |
| Read/write/notify characteristic | `0000FFE1-0000-1000-8000-00805F9B34FB` |
| Status header | `AA 66` |
| Status length | 20 bytes |

## Status frame

| Offset | Field | Interpretation |
| --- | --- | --- |
| 0-1 | Header | `AA 66` |
| 3 | Running state | Controller state value |
| 5 | Running step | Controller step value |
| 6-7 | Altitude | Little-endian unsigned value |
| 8 | Running mode | `1` level, `2` temperature; other observed modes use byte 10 for level |
| 9 | Set value | Level in level mode; target temperature in temperature mode |
| 10 | Active level | Zero-based level in temperature and manual modes |
| 11-12 | Supply voltage | Little-endian unsigned value, divided by 10 |
| 13-14 | Case temperature | Little-endian value; values above 350 use a tenth-degree scale |
| 15-16 | Cabin temperature | Little-endian signed 16-bit value |
| 17 | Error code | AA66-specific error position |

The AirHeaterBLE parser reads AA66 error information from byte 17, unlike AA55,
which uses byte 4. It also reads altitude from bytes 6-7 and cabin temperature
from bytes 15-16.

## Commands

AA66 control packets are always eight unencrypted bytes:

```text
AA 55 PIN_HI PIN_LO COMMAND ARG_LO ARG_HI CHECKSUM
```

`PIN_HI` is `PIN // 100`; `PIN_LO` is `PIN % 100`. The checksum is the sum of
bytes 2 through 6 modulo 256. The command header remains `AA 55` even when the
status protocol is AA66.

## Detection

The integration selects AA66 only for a 20-byte notification headed `AA 66`.
It does not infer AA66 from a BLE service UUID alone.
